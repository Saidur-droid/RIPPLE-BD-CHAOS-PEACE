# JUDGE-READY FINAL SPRINT — 27 SEP 2026

## Positioning

RIPPLE BD is not another awareness quiz. It is a **digital peace simulator**:

**natural decision → visible ripple → human consequence → REWIND → safer practice → reflection**

The product already demonstrates this loop. The remaining competitive work is evidence, reliability, iteration, and presentation.

## What should make judges remember it

### 1. The judge becomes the user
Do not spend the first minute explaining the architecture. Put a fictional post on screen and ask the judge to choose.

### 2. Make REWIND the signature moment
The interface should visually stop after the consequence, reverse the moment, and give the user a second chance. The line to land is:

> “We do not only tell young people what responsible digital citizenship looks like. We let them feel the consequence of a reflex, rewind it, and practise a safer one.”

### 3. Evidence on the same slide as humility
Show one local pilot chart and explicitly label the design as a preliminary convenience pilot. Credibility is stronger than inflated claims.

### 4. Show the product changed because of users
A simple “Before pilot → Feedback → After pilot” card can be more persuasive than another feature list.

## 60-second demo choreography

**0–10s** — A fictional viral post appears. “You are in Nodi. What would you do first?”

**10–20s** — Judge chooses. Do not coach the answer.

**20–35s** — Ripple Engine shows reach/hostility/safety/trust indicators and one human consequence.

**35–45s** — REWIND. Same decision point returns.

**45–55s** — Judge chooses a safer response. Show the changed consequence.

**55–60s** — “Every click has a consequence. RIPPLE trains the reflex before a real crisis does.”

## What “massive impact” requires after selection

A simulator alone is not mass impact. Build a repeatable delivery system around it:

1. **Ripple Labs** — 20–30 minute facilitated sessions using the simulator.
2. **Train-the-facilitator kit** — short script, safeguarding rules, QR, reflection prompts.
3. **Day 3 / Day 7 boosters** — unseen mini-scenarios to test retention.
4. **Campus/youth-club cohorts** — measurable batches, not vanity reach.
5. **Scenario co-design loop** — youth feedback informs future fictional scenarios.
6. **Public learning dashboard later** — only aggregated, privacy-safe evidence after there is enough real data.

## Judge Q&A defense

**“Is this just a game?”**  
It is a scenario-based practice environment with explicit learning objectives and pre/post measurement.

**“Are those consequence numbers real-world predictions?”**  
No. They are deterministic simulation indicators, clearly labelled as such.

**“What is actually innovative?”**  
Not simulation alone. The differentiator is the closed loop: instinct → consequence → rewind → safer retry → skill cues → retention measurement.

**“Can this scale with BDT 50,000?”**  
The core software is zero-paid and browser based, so fellowship funding can go to delivery, facilitation, testing, accessibility, content refinement, and community reach rather than infrastructure.

**“What if the pilot is weak?”**  
Report it transparently, fix the biggest usability/learning issue, and show the iteration. Weak honest evidence plus visible improvement is more credible than perfect-looking invented evidence.
