# Zero-Cost Build Strategy

The user constraint is explicit: **no paid tools or paid services for the MVP**.

## Product

| Need | Zero-cost choice |
|---|---|
| Frontend | React + Vite + TypeScript |
| Styling | Tailwind CSS |
| Motion | Motion / CSS |
| Icons | Lucide |
| Scenario logic | Local TypeScript/JSON |
| State | Browser storage |
| Hosting | GitHub Pages |
| Repository | GitHub |
| Forms | Google Forms |
| Analysis | Google Sheets / local Python |
| Wireframes | Figma free tier or browser code |
| QR | open-source client-side library |
| Fonts | system / open fonts |

## Cost discipline

Do not add:
- paid LLM API,
- paid database,
- paid analytics,
- paid stock assets,
- paid form tool,
- paid design system,
- paid hosting.

## Why this is strategically good

Zero-paid MVP:
- proves feasibility,
- makes live demo more reliable,
- reduces grant dependence,
- allows more fellowship budget to reach community implementation,
- eliminates API-credit failure risk.

## Fellowship budget philosophy

If selected, use grant money primarily for:
- community sessions,
- participant materials,
- local travel,
- outreach,
- accessibility/localization,
- measurement,
- content production.

Software cost should remain near zero where possible.
