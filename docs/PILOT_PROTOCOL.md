# Pilot Protocol

## Purpose

Generate honest, useful evidence before submission:
- usability,
- comprehension,
- immediate learning,
- product defects,
- safeguarding concerns.

## Target

**20–30 youth** from the team's target division.

This is a convenience pilot, not a representative study.

## Recruitment

Prefer:
- university/college peers,
- youth clubs,
- community groups,
- diverse digital-skill levels.

Do not require participants to disclose victimization.

## Session flow

1. Consent / study notice — 1 min
2. Baseline mini-scenario set — 2 min
3. RIPPLE MVP — 6–8 min
4. Parallel post-scenario set — 2 min
5. usability questions — 2 min
6. optional anonymous quote — 1 min

Total: roughly 15 minutes.

## Day-7 follow-up

Use a random code generated at baseline.
Send a link manually.
No login required.

## Questions to test

### Learning
- Did the user check source/context more often after the experience?
- Did the user choose safer bystander responses?
- Can the user identify a manipulation technique?

### UX
- Where did the user hesitate?
- Was REWIND understandable?
- Did the simulation feel realistic without feeling exploitative?
- Did the score explanation make sense?

### Safeguarding
- Did any content feel needlessly distressing?
- Did any scenario appear to stereotype a real community?
- Was SHIELD Mode clear that it is educational, not emergency support?

## Stop conditions

Pause the pilot if:
- a scenario is interpreted as targeting a real community,
- multiple users report distress beyond mild discomfort,
- result scores are misunderstood as moral/mental-health judgments,
- data cannot be collected without identifying participants.

## Deliverables

Before application:
- one clean chart: baseline vs immediate post,
- one completion metric,
- one learning insight,
- one product change made because of pilot feedback,
- 1–2 optional anonymized quotes.

Never fabricate numbers to fill the deck.
