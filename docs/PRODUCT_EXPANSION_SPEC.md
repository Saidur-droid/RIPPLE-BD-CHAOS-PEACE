# RIPPLE BD — Production-Grade Expansion Spec

> Status: locked direction for post-MVP product hardening and scale.

## 1. Core product rule

RIPPLE must show how a small digital action can create a chain of consequences for another person.

Each scenario must make this understandable without requiring facilitator explanation:

**small action → amplification → social consequence → human consequence → reflection → REWIND → safer response**

All scenarios remain fictional or clearly fictionalized composites inspired by documented real-world patterns. Do not copy real victim stories or imply a fictional scenario depicts a specific real person.

## 2. Scenario library target

Build toward **80–90 complete scenarios** across multiple learning categories.

A user session shows **exactly 3 complete scenarios**.

On a later session, the engine should serve a different set of 3 where possible.

Rules:
- never show half a scenario
- never split one scenario across sessions
- each scenario must contain full MIRROR → RIPPLE → HUMAN CONSEQUENCE → REWIND → PEACE → REFLECT
- avoid immediate repeats using local session history
- keep difficulty balanced across the 3 scenarios
- preserve deterministic scoring
- every scenario must be understandable in plain language

## 3. Scenario families

Target scenario families:
- misinformation / missing context
- edited or cropped media
- rumor amplification
- cyberbullying
- sexualized harassment
- doxxing / privacy leakage
- impersonation / fake accounts
- exclusion and pile-ons
- hate or identity-based generalization
- communal tension
- manipulated screenshots
- deepfake / synthetic-media literacy
- scam / emotional manipulation
- public shaming
- victim-blaming
- unsafe bystander behavior
- source diversity / missing voices
- escalation vs de-escalation
- platform reporting choices
- peer pressure / social proof

## 4. Human consequence storytelling

Every scenario should include at least one concrete fictional human consequence, for example:
- a student stops attending class after a pile-on
- a family member receives threatening messages after a rumor spreads
- a community event is cancelled because of escalating tension
- a target loses control of a private image or post
- an innocent person becomes associated with a false claim
- a minority voice is excluded while outsiders define the story
- a friendship or peer group fractures because of amplification

The tone must be serious but non-graphic. Avoid trauma exploitation.

## 5. Numbers and judge-facing data

Use two types of numbers only:

### A. Product simulation indicators
Reach / hostility / safety / trust.

These are clearly labelled as **simulation indicators, not real-world effect sizes**.

### B. Verified external statistics
Only use current, sourceable statistics from credible institutions or research.

Never invent:
- “X people harmed by one share”
- fake conversion rates
- fake national impact
- fake pilot improvement

Judge-facing shock should come from **credible scale + human consequence**, not fabricated precision.

## 6. National-scale architecture

RIPPLE should be deployable nationally through:
- browser-first delivery
- Bangla + English
- facilitator mode
- train-the-trainer materials
- university/college cohorts
- youth club sessions
- NGO/community partners when verified
- low-bandwidth fallback
- printable/QR facilitator kit
- Day 3 / Day 7 booster scenarios
- privacy-safe cohort measurement

## 7. International-ready architecture

Keep the engine locale-agnostic:
- language packs separated from logic
- region-specific scenario packs
- cultural review before publication
- common skill taxonomy
- shared scoring framework
- country-specific safeguarding notes

Goal: Bangladesh first, reusable framework internationally.

## 8. Product jaw-drop moments

Locked product moments:
1. **Consequence Cascade** — one small click visibly spreads through a fictional network.
2. **Human Face Moment** — the metric view transitions to a concrete human consequence.
3. **REWIND** — the signature reversal.
4. **Second-Life Outcome** — the same moment plays out differently after a safer choice.
5. **Reflex Profile** — user sees what digital reflexes they practiced.
6. **Return Variety** — future sessions serve a different 3-scenario set.

## 9. UX rule

Every screen must answer one question:
- What happened?
- Why did it happen?
- Who was affected?
- What could I do differently?

If a user needs a developer beside them to understand a screen, the screen is not finished.

## 10. Integrity

Massive impact claims must be earned through:
- real participant data
- completion data
- pre/post measurement
- retention
- documented facilitator delivery
- documented iteration

No fabricated evidence.
