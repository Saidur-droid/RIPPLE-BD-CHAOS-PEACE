# Contributing

## Branching

- `main`: stable
- `feat/*`: product features
- `fix/*`: bug fixes
- `docs/*`: documentation
- `research/*`: evidence/measurement changes

## Pull request checklist

- [ ] Change has one clear purpose
- [ ] Mobile behavior checked
- [ ] No paid dependency introduced
- [ ] No sensitive personal data introduced
- [ ] Scenario changes reviewed for stereotypes / real-person resemblance
- [ ] Measurement copy distinguishes simulation metrics from real-world facts
- [ ] Sources added for external factual claims
- [ ] No fabricated pilot result or partnership claim
- [ ] Accessibility basics checked
- [ ] Screenshots/video added for major UI changes

## Content review

Scenario PRs require review from:
- Product/Tech lead
- Research/Safeguarding lead

Community-facing copy should also be reviewed by the Community/Creative lead.

## Commit style

Prefer:
- `feat: add rewind transition`
- `fix: correct mobile feed overflow`
- `docs: add pilot protocol`
- `research: update evidence note`

## Definition of ready

A feature is ready for pilot only if it can be used without verbal explanation from the developer.
